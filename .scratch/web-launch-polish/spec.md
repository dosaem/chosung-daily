# 웹 출시 품질 업데이트 + 대결 링크

배경·근거: `.scratch/store-launch/competitive-analysis.md`(경쟁 7개 캡처 비교, 2026-10-16).
사용자 결정(2026-10-16): 웹을 앱 목업(S1·S2) 수준으로 전부 맞추고, 차별 기능으로 **대결 링크**를 같이 만든다. 다음 안 3개는 기획만(Further Notes).

## Problem Statement

웹(`https://chosung.dosaem.com`)에 처음 들어온 플레이어는 `ㅎ ㄱ · 2글자 · 남은 기회 5/5` 와 입력창만 본다. 무엇을 하는 게임인지, 몇 번 기회가 있는지, 틀리면 무슨 피드백이 오는지, 내일은 언제 새 문제가 오는지 화면이 말해주지 않는다. 시도 보드는 첫 제출 뒤에야 그려지고, 결과는 공유 버튼 하나다. 메인 화면 아래에는 사업자 정보 표가 통째로 붙어 있어 게임보다 법적 고지가 더 크다. Wordle·꼬들·꼬맨틀·Contexto 는 전부 첫 화면에서 규칙 한 줄·시도 보드·결과 시트·다음 퍼즐 시각을 보여준다.

그리고 경쟁 서비스 대비 **나은 점이 하나도 없다.** 친구에게 결과를 보내도 친구는 같은 퍼즐을 풀 뿐, 서로 비교할 길이 없다.

## Solution

1. 웹 오늘 화면을 앱 목업 S1(게임 홈)·S2(결과 시트)와 같은 요소로 채운다: 첫 방문 "어떻게 하나요?" 모달, 퍼즐 헤더(날짜·번호·카테고리·새 퍼즐 시각), 5행 시도 보드(빈 행 포함), 힌트 카드(잠김/열림), 결과 시트(정답·내 그리드·시도별 정답자 비율·다음 퍼즐 카운트다운·공유·순위 보기), 푸터 정리(약관 링크 한 줄 + 접힌 사업자 정보). 디자인 시스템(OVERRIDES 토큰)과 문구 사전(ko/en) 체계는 그대로 쓴다.
2. **지난 퍼즐 아카이브**(2026-10-16 추가): 하루 한 판으로 끝나지 않게 지난 7일 퍼즐을 누구나, 그 이전은 구독자가 푼다. 기록·순위는 오늘 퍼즐만의 것이라 아카이브는 건드리지 않는다.
3. **대결 링크**: 결과를 공유할 때 링크가 함께 나간다. 친구가 그 링크로 들어오면 "게스트 #a3f1 님이 2회 · 41초 만에 풀었어요 — 이겨보세요" 배너를 보고 같은 퍼즐을 푼다. 다 풀면 두 사람의 시도 수·시간이 나란히 나오고 이긴 쪽이 표시된다. 공유 텍스트에는 이 링크가 다시 들어가 다음 사람에게 이어진다. 상대는 익명 태그로만 보인다(리더보드와 같은 노출 수준).

## User Stories

### 첫 방문·규칙
1. As a 처음 온 플레이어, I want 화면 첫 줄에서 "초성만 보고 단어를 맞히는 하루 한 문제, 기회 5번" 을 읽고 싶다, so that 뭘 해야 하는지 바로 안다.
2. As a 처음 온 플레이어, I want 첫 방문에 "어떻게 하나요?" 모달이 한 번 뜨길 원한다, so that 규칙·피드백 색·새 퍼즐 시각을 한 장에서 익힌다.
3. As a 플레이어, I want 헤더의 `?` 버튼으로 언제든 그 모달을 다시 열고 싶다, so that 규칙을 잊어도 찾을 수 있다.
4. As a 플레이어, I want 모달이 내 UI 언어(ko/en)로 나오길 원한다, so that 영어 사용자도 같은 안내를 받는다.
5. As a 플레이어, I want 모달을 닫으면 다시 자동으로 뜨지 않길 원한다, so that 매번 방해받지 않는다(브라우저 저장 실패 시엔 매번 떠도 된다).

### 퍼즐 헤더
6. As a 플레이어, I want 날짜 줄에 `10월 16일 · No. 342 · 일반 단어` 를 보고 싶다, so that 오늘이 몇 번째 퍼즐인지 알고 공유 텍스트와 맞춘다.
7. As a 플레이어, I want `KST 00:00 새 퍼즐` 칩을 보고 싶다, so that 다음 퍼즐이 언제 오는지 안다.
8. As a 영어 플레이어, I want 날짜·번호가 영어 형식(`Oct 16 · No. 342 · Common word`)으로 나오길 원한다.
9. As a 플레이어, I want 한국어/영어 퍼즐 전환이 헤더의 작은 토글이길 원한다, so that 본문이 퍼즐에 집중된다.

### 시도 보드·힌트
10. As a 플레이어, I want 제출 전에도 빈 5행이 그려져 있길 원한다, so that 기회가 5번임이 한눈에 보인다.
11. As a 플레이어, I want 제출한 행이 글자별로 초록(자리까지 맞음)/회색(아님)으로 칠해지길 원한다, so that 다음 추측을 좁힌다.
12. As a 플레이어, I want 입력 중인 글자가 다음 빈 행에 실시간으로 보이길 원한다, so that 몇 글자 썼는지 안다. (입력창은 유지 — 한글 조합 입력 때문에 키보드 UI 는 만들지 않는다)
13. As a 플레이어, I want 글자 수 카운터 `0/4` 를 입력창 안에서 보고 싶다.
14. As a 플레이어, I want 힌트 카드가 잠김 상태("힌트는 3번째 오답 후 열려요")로 처음부터 보이길 원한다, so that 힌트가 있다는 걸 알고 버틴다.
15. As a 플레이어, I want 3번째 오답 뒤 카드가 열려 힌트 문장이 보이길 원한다.
16. As a 플레이어, I want 글자 수가 다른 추측을 내면 시도를 안 쓰고 인라인으로 "4글자로 입력하세요" 를 보고 싶다.
17. As a 플레이어, I want 자정이 지나 퍼즐이 바뀌었으면 "새 퍼즐이 있어요 — 새로고침" 안내를 보고 싶다(기존 409 처리 유지).

### 결과 시트
18. As a 정답을 맞힌 플레이어, I want "정답은 지하철역! 3번째 시도만에" 결과 시트가 보드 위로 뜨길 원한다.
19. As a 못 맞힌 플레이어, I want "아쉬워요, 정답은 지하철역" 과 같은 시트를 보고 싶다.
20. As a 플레이어, I want 시트에 내 시도 그리드(타일)가 보이길 원한다, so that 공유 전에 어떻게 보일지 안다.
21. As a 플레이어, I want 시도 1~5회별 정답자 비율 막대와 내 행 강조를 보고 싶다, so that 남들과 비교한다.
22. As a 플레이어, I want "다음 퍼즐까지 07:12:33" 카운트다운을 시트에서 보고 싶다.
23. As a 플레이어, I want "결과 공유" 가 주 버튼, "순위 보기" 가 보조 버튼이길 원한다.
24. As a 플레이어, I want 시트를 닫아도 보드·결과가 남고 "결과 보기" 버튼으로 다시 열리길 원한다.
25. As a 처음 완료한 플레이어, I want 시트 아래 "기록을 지키려면 계정을 연결하세요 →" 한 줄을 보고 닫을 수 있길 원한다(1회).
26. As a 플레이어, I want 공유 텍스트가 `오늘의 초성 10월 16일 · No. 342 · 3/5` + 가림 줄 + 이모지 그리드 + 대결 링크이길 원한다, so that 정답이 새지 않고 받는 쪽이 오늘 것임을 안다.

### 푸터·사업자 정보
27. As a 플레이어, I want 메인 화면 아래가 약관·개인정보처리방침·계정 삭제 링크 한 줄이길 원한다.
28. As a 플레이어, I want 사업자 정보가 "사업자 정보" 토글로 접혀 있고 펼치면 전부 보이길 원한다, so that 고지는 있되 게임을 가리지 않는다.
29. As a 운영자, I want 접힌 상태에서도 상호·대표자·사업자등록번호·연락처가 HTML 에 그대로 있길 원한다, so that 전자상거래법 표시 의무를 지킨다.
30. As a 플레이어, I want "앱으로 플레이" 배지(스토어 링크 설정 시)가 푸터에 남아 있길 원한다.

### 대결 링크 — 보내는 쪽
31. As a 완료한 플레이어, I want 공유 텍스트 끝에 대결 링크가 붙길 원한다, so that 받은 친구가 같은 퍼즐로 바로 들어온다.
32. As a 플레이어, I want 링크에 내 이메일·게스트 토큰이 들어가지 않길 원한다, so that 공유해도 기록이 새지 않는다.
33. As a 플레이어, I want 링크가 오늘 퍼즐(그 언어)에만 유효하길 원한다, so that 내일 들어온 사람에게 엉뚱한 비교가 안 보인다.
34. As a 플레이어, I want 아직 안 끝낸 상태에서는 링크가 만들어지지 않길 원한다, so that 미완성 결과로 대결이 안 걸린다.

### 대결 링크 — 받는 쪽
35. As a 링크로 들어온 플레이어, I want 상단에 "게스트 #a3f1 님이 2회 · 41초 만에 풀었어요 — 이겨보세요" 배너를 보고 싶다(초는 첫 시도부터 정답까지 걸린 시간).
36. As a 링크로 들어온 플레이어, I want 상대가 못 풀었으면 "게스트 #a3f1 님은 5번 다 틀렸어요 — 맞혀보세요" 를 보고 싶다.
37. As a 링크로 들어온 플레이어, I want 내 퍼즐 언어가 상대와 다르면 "이 대결은 영어 퍼즐이에요 — 영어로 바꾸기" 버튼을 보고 싶다.
38. As a 링크로 들어온 플레이어, I want 다 풀고 나면 결과 시트에 "나 2회 · 35초 vs 게스트 #a3f1 2회 · 41초 → 내가 이겼어요" 비교 카드를 보고 싶다.
39. As a 링크로 들어온 플레이어, I want 비교 기준이 분명하길 원한다: 성공이 실패를 이기고, 둘 다 성공이면 시도 적은 쪽, 같으면 소요 시간 짧은 쪽, 그것도 같으면 무승부.
40. As a 링크로 들어온 플레이어, I want 둘 다 못 맞혔으면 "둘 다 아쉬워요" 무승부로 보고 싶다.
41. As a 링크로 들어온 플레이어, I want 내 공유 텍스트에도 대결 링크(내 것)가 들어가길 원한다, so that 다음 친구에게 이어진다.
42. As a 링크로 들어온 플레이어, I want 어제 링크(48시간 안)를 열면 "지난 대결이에요 — 오늘 퍼즐을 풀어보세요" 를 보고 평소처럼 플레이하길 원한다(그보다 오래된 링크는 복호화 실패로 배너 없이 평소 화면).
43. As a 링크로 들어온 플레이어, I want 링크가 깨졌거나 상대가 아직 안 끝냈으면 배너 없이 평소 화면을 보길 원한다.
44. As a 이미 오늘 퍼즐을 끝낸 플레이어, I want 대결 링크를 열면 바로 비교 카드가 보이길 원한다.
45. As a 플레이어, I want 대결 배너를 닫을 수 있길 원한다(이번 세션만).
46. As a 플레이어, I want 자기 링크를 열면 "내 대결 링크예요 — 친구에게 보내세요" 를 보길 원한다.

## Implementation Decisions

### 화면 (웹만, 앱은 범위 밖)
- 오늘 화면 요소는 SCREENS.md S1/S2 를 따르되 웹 차이만 둔다: 보상형 광고 버튼 없음, 결과 시트는 바텀시트 대신 중앙 다이얼로그(`<dialog>`), 하단 탭 대신 기존 섹션 내비 유지.
- "어떻게 하나요?" 모달은 온보딩 3장(S6)을 한 장으로: 예시 가림 타일(ko `ㅈㅎㅊㅇ`, en `_PPL_`), 피드백 색 설명, "기회 5번 · 힌트는 3번째 오답 후", "매일 KST 00:00 새 퍼즐". 본 적 있음 표시는 브라우저 저장(실패해도 동작).
- 퍼즐 번호는 서버가 준다: 오늘 퍼즐 응답에 `number` = `COUNT(daily_puzzle WHERE language=? AND puzzle_date <= 그 퍼즐의 puzzle_date)` 을 추가한다(오늘 퍼즐엔 오늘 번호, 지난 퍼즐엔 그 날 번호 — `cache_puzzle(puzzle)` 이 `puzzle.puzzle_date` 를 쓰면 아카이브도 그대로 맞는다). COUNT 는 뷰가 아니라 `cache_puzzle`(또는 공용 헬퍼) 안에서 계산해 Redis `CachedPuzzle` 페이로드에 넣는다 — `puzzle_service` 와 자정 워밍(`puzzle_maintenance_service`) 두 경로가 같은 값을 넣도록(날짜별 키라 따로 무효화할 게 없고, 과거 날짜 배정은 거부되므로 번호는 안정적이다). `get_cached_puzzle` 은 `number` 가 없는 **옛 페이로드를 캐시 미스로 취급해 재채움**한다 — 무중단 배포 직후 옛 캐시를 읽어 KeyError 로 자정까지 500 이 나지 않게(테스트: 옛 모양 페이로드를 심고 조회). 앱 응답 스키마에 필드가 늘어도 앱은 무시하므로 호환.
- 시도 보드는 기존 `renderBoard`/`renderAttemptRow` 를 확장해 빈 행을 `length` 만큼 `tile-empty` 로 채운다. 입력 중 미리보기는 다음 빈 행에 글자를 그리고 제출 시 피드백으로 교체.
- 힌트 카드는 응답의 `hint` 로 그린다: `null` 이면 잠김("3번째 오답 후 열려요"), 문장이 오면 열림. 조회·제출 응답 둘 다 같은 규칙(서버 `compute_reveal`). `hint_unlocked` 는 앱의 보상형 "힌트 미리 보기" 플래그라 웹에서는 쓰지 않는다. 서버 변경 없음.
- 결과 시트의 통계 막대는 완료 제출 뒤 이미 도는 `loadTodayStats()` 의 **같은 응답**으로 시트 막대와 순위 탭을 함께 그린다(요청을 늘리지 않는다). "다음 퍼즐까지" 카운트다운은 기존 `renderCountdown` 을 대상 요소·문구 키를 인자로 받게 일반화해 상태 카드와 시트가 같이 쓴다.
- 푸터 사업자 정보: `index.html` 의 `_business_info.html` include 만 `<details><summary>` 로 감싼다(조각은 `/terms`·`/privacy` 와 공유라 손대지 않는다). `summary` 문구는 `ui_strings` 키. 접힘 상태에서도 모든 텍스트는 DOM 에 있다. `summary` 줄에는 상호·연락처를 노출한다; 상호(`LEGAL_BUSINESS_NAME`)가 비어 있으면 조각과 같은 서비스명 문구(`ui_strings` 키, `service_value`) + `contact_email` 로 대신한다(레포에 상호를 적지 않는 규칙 유지). 전자상거래법 "초기 화면 표시" 절충 — 미정 항목 참고.
- 문구는 전부 `app/utils/ui_strings.py` 사전(ko/en)에 추가한다. 템플릿·JS 에 리터럴 문구를 두지 않는다(기존 규칙).

### 대결 링크
- **토큰은 상태 없는 암호문**이다. 기존 `app/utils/crypto.py` 의 Fernet 파생 패턴을 용도 상수만 `challenge-link` 로 바꿔 재사용해 `{guest_id, puzzle_id}` 를 **암호화**한다(서명만 하는 `URLSafeSerializer` 는 base64 를 풀면 게스트 ID 원본이 보여 "게스트 ID 원본은 응답에 넣지 않는다" 규칙(README 38, `anon_tag`)에 걸린다 — `anon_tag` 는 ID 의 하위 16비트라 ID 를 알면 역산된다). 테이블·만료 작업이 없고, 퍼즐 ID 가 박혀 있어 자정이 지나면 자연히 "지난 대결" 이 된다. 게스트 토큰·이메일은 들어가지 않는다. 페이로드는 JSON 대신 `"<guest_id>:<puzzle_id>"` 바이트로 줄이고(Fernet 은 그래도 약 100자), Fernet 타임스탬프 `ttl` 48시간을 복호화에 걸어 "지난 대결" 판정의 2중 안전장치로 둔다.
- 발급: `POST /api/v1/puzzles/today/challenge` (Bearer, `{puzzle_id}`) → 조회 GET 과 **같은 사실 객체 + `url`**: `{url, anon_tag, status, attempts, elapsed_seconds, puzzle_id}` (내 값도 DB `Attempt` 행에서 — 웹이 시계를 재면 다른 기기 완료·새로고침에서 틀린다). 웹은 이 응답을 메모리에 두고 비교 카드의 "나" 칸에 쓴다. 그 게스트가 그 퍼즐을 **끝낸 경우에만**(성공·실패) 발급, 아니면 409 `NOT_FINISHED`(`app/errors.py` 에 클래스 추가, 번들 `ERROR_STRING_KEYS` 와 `ui_strings` ko/en 문구 키 추가). 퍼즐 불일치는 기존 409 `PUZZLE_CHANGED`.
- 조회: `GET /api/v1/challenges/<token>` (Bearer — 조회자도 게스트여야 비교 기준이 있다) → `{anon_tag, language, puzzle_date, puzzle_id, status(success|fail), attempts, elapsed_seconds, is_me, is_today}`. **사실의 출처는 DB `Attempt` 행**이다(리더보드 ZSET 은 정답자만 있고 Redis 장애면 비어 있다): `attempts = COUNT`, `status` 는 정답 행이 있으면 `success`, 5회 다 틀렸으면 `fail`, 그 외(미완료)는 404. `elapsed_seconds` = 첫 시도 `created_at` → 마지막 시도 `created_at` 의 초(첫 시도에 맞히면 0). 복호화 실패 404 `NOT_FOUND`, 퍼즐이 오늘이 아니면 `is_today: false` 로 200(화면이 "지난 대결" 문구).
- rate limit: 발급 POST 는 제출과 **다른 키**(`ratelimit:challenge:{guest_id}`, 분당 10회)로 제한한다 — 기존 `rate_limited` 는 키가 `ratelimit:guess:` 하나라 그대로 쓰면 `?vs=` 새로고침이 제출 예산을 깎는다; 키 접두사를 인자로 받게 일반화한다(데코레이터가 팩토리가 되므로 `app/api/puzzles.py` 의 `@rate_limited` 와 `tests/test_rate_limit.py` 를 같이 고친다). 조회 GET 은 제한하지 않는다(복호화 실패가 곧 404 라 비용이 없다).
- 상대 식별은 리더보드와 같은 `anon_tag`(puzzle_metrics) 만. 성공자의 시도 수는 리더보드에 이미 공개되는 값이다. **실패자**의 시도 수·소요 시간은 지금 집계(비율)로만 공개되는 새 노출인데, 링크는 본인이 스스로 발급해 보낸 것이고 익명 태그 외 식별 정보가 없어 수용한다(스펙 결정 2026-10-16).
- 승패 판정은 서버가 하지 않는다 — 두 결과를 받은 웹이 비교한다. 규칙은 **성공 > 실패** → 둘 다 성공이면 **시도 적은 쪽** → 같으면 **소요 시간(`elapsed_seconds`) 짧은 쪽** → 같으면 무승부 → 둘 다 실패면 무승부. 리더보드의 `seconds` 는 "KST 자정부터 푼 시각까지" 라 대결엔 쓰지 않는다(그 기준이면 링크를 받은 쪽은 시도 수가 같을 때 영원히 못 이긴다). 서버는 사실만 준다.
- 웹: `?vs=<token>` 은 `restart()` 에서 게스트 토큰을 확보한 뒤(조회 GET 이 Bearer 라 첫 방문자는 `ensureToken()` 다음) 오늘 퍼즐 조회와 병행해 조회한다. 토큰은 먼저 세션 저장소에 두고 `history.replaceState` 로 URL 에서 지운다(`login_token` 과 같은 처리) — 받은 쪽이 주소창을 복사해 보내도 **보낸 사람의** 대결이 계속 전파되지 않게. 게스트 발급 실패로 멈추면 세션 저장소의 토큰은 유지해 재시도 버튼이 다시 조회한다. 새로고침은 세션 저장소로 유지, 탭을 닫으면 소멸. 배너는 비모달 영역(`role="region"` + `aria-label` + 닫기 버튼, OfflineBanner 와 같은 자리)이고, 첫 방문 모달이 같이 생기면 모달이 닫힌 뒤 배너를 보인다. ESC 는 모달·결과 시트(`<dialog>`)에만. 완료 시 결과 시트에 비교 카드.
- 내 대결 링크 발급 시점: 제출로 끝났을 때뿐 아니라 조회 응답이 이미 끝난 상태(다른 기기에서 완료)일 때도 결과 시트를 그리면서 **1회** 발급해 메모리에 둔다. 실패하면 공유 텍스트는 기존 `SHARE_URL` 로 폴백.
- 공유 텍스트(완료 뒤): 첫 줄 `오늘의 초성 10월 16일 · No. 342 · 3/5`(실패는 `X/5`) → 가림 줄(`share_puzzle`, 기존 유지) → 이모지 그리드 → 마지막 줄 **대결 링크** `https://chosung.dosaem.com/?vs=<token>&utm_source=share`. 이 줄이 기존 `SHARE_URL`(`?utm_source=share`) 줄을 **대체**한다. 발급 실패(오프라인·409·5xx)면 기존 `SHARE_URL` 로 폴백해 공유 자체는 막히지 않는다. 날짜는 유지한다(공유 받는 쪽이 "오늘 것" 임을 알아야 한다). `tests/test_web_js.py` 의 마지막 줄 단정과 `tests/e2e/web/specs` 의 공유 시나리오를 함께 갱신한다.
- 언어 불일치: 대결의 `language` 와 내 퍼즐 언어가 다르면 배너에 "○○로 바꾸기" 버튼(기존 언어 전환 호출).
- 접속기록(개인정보 감사 로그) 대상 아님 — 익명 태그·공개 지표만 다룬다.


### 지난 퍼즐 아카이브
- **범위**: `puzzle_date < 오늘(KST)` 이고 배정된 날짜만. 어제부터 7일 전까지는 누구나, 그보다 전은 `entitlement_for(guest).active` 일 때만(앱 구독 = 웹에서도 같은 게스트면 인정). 오늘·미래·미배정 날짜는 404 `NOT_FOUND`(미래 퍼즐 노출 차단, US 65). 어제까지의 퍼즐만 "지난 퍼즐" 이고 오늘은 오늘 경로(`/puzzles/today`)만 쓴다 — 자정 경계 규칙(CONTEXT.md "오늘의 퍼즐"/"퍼즐 고정", `puzzle_service.get_today_puzzle_or_404` 독스트링 — `docs/adr/` 는 아직 비어 있어 이 티켓에서 ADR 로 쓴다)을 안 건드린다.
- **API**: `GET /api/v1/puzzles/archive?language=&days=7` → `{first_date, days: [{date, number, status: success|fail|in_progress|none|locked}]}`(최근 날짜부터; `days` 상한은 `/me/history` 와 같은 31; `locked` 는 구독 필요; `first_date` 는 구독자 날짜 선택기의 `min`). 통계·리더보드처럼 이 목록만 `?language=` 를 받는다. `GET /api/v1/puzzles/{date}` → 오늘 응답과 같은 모양(`TodayPuzzleResponse`) + `archived: true` + 끝났으면 `answer`. `POST /api/v1/puzzles/{date}/guesses` → 오늘 제출과 같은 응답. **두 경로의 언어는 `guest.puzzle_language`** 다(오늘 경로와 같은 이유 — 플레이 중인 퍼즐이 요청마다 달라지면 안 된다; US 63 의 토글은 `PATCH /me` 라 띠도 따라온다). `{date}` 는 ISO 문자열로 받아 파싱 실패는 404(정적 규칙 `today`·`archive` 가 먼저 매칭되므로 충돌 없음). 잠긴 날짜(8일 전 이상, 비구독자)는 GET·POST 모두 **403 `SUBSCRIPTION_REQUIRED`**(`app/errors.py` 클래스 추가, `ERROR_STRING_KEYS`·`ui_strings` "구독하면 전부 풀 수 있어요") — 목록의 `locked` 는 표시일 뿐 차단은 서버가 한다. 구독 판정은 `build_entitlement(find_by_guest(guest.id), utcnow())` 로 — `entitlement_for` 는 재확인 주기마다 스토어 API 를 동기 호출하므로 `/me/stats` 한 곳에만 둔다. 아카이브 제출도 오늘 제출과 같은 `@rate_limited`(`ratelimit:guess:`) 를 탄다. 힌트 미리 보기(`hint-unlock`)는 아카이브에 없다(광고 보상 경로 없음).
- **제출 로직 재사용**: `guess_service.submit_guess` 의 "오늘 퍼즐 조회" 를 "주어진 퍼즐" 로 일반화한다(`submit_guess(guest, puzzle, raw_guess, *, counts_for_records: bool)`), `get_today_puzzle_view(guest)` 도 `(guest, puzzle)` 로. 아카이브는 `counts_for_records=False` — 트랜잭션 안의 `_record_solve`(GuestStats 연속·누적)와 `_record_metrics`(리더보드 ZSET·통계 HINCRBY·DailyStats) **둘 다** 건너뛰고, `lock_for_guest`·`_hold_the_puzzle_answer` 는 그대로 탄다(US 56). `Attempt` 행은 그대로 `puzzle_id` 로 저장되므로 테이블 변경이 없고, 이어서 풀기(US 61)와 재플레이 불가(US 60)는 기존 시도 조회로 된다. 퍼즐 고정(`puzzle_id`)과 `PUZZLE_CHANGED` 규칙은 아카이브에서도 같다.
- **캐시**: 지난 퍼즐은 바뀌지 않으므로 `puzzle:{date}:{lang}` 캐시를 그대로 쓴다(`cache_puzzle` 재사용, TTL 26시간은 아카이브 조회에서도 충분 — 자주 열리는 날짜만 다시 채워진다).
- **내 기록 `GET /me/history`** 는 `Attempt` 조인이라 서버 변경 없이 지난 날짜 칸이 아카이브 결과로 채워진다. 웹 띠의 상태 점도 같은 함수(`summarize_by_date_and_language`)를 재사용한다. 연속 기록 계산은 `GuestStats.last_solved_date` 기반이라 영향 없다.
- **웹**: 결과 시트 아래와 "내 기록" 탭에 지난 7일 띠. 날짜를 고르면 오늘 화면의 보드 컴포넌트를 `archived` 모드로 재사용(헤더에 날짜·`지난 퍼즐`, 통계·카운트다운·대결 배너 숨김, "오늘 퍼즐로" 버튼). 잠긴 날짜는 자물쇠 + 구독 안내(웹은 앱 설치 배지로 연결 — 웹 결제 없음). 구독자는 날짜 선택기(`<input type="date">`, min = 첫 퍼즐 날짜, max = 어제).
- **공유 텍스트**: 첫 줄 `오늘의 초성 10월 9일 · No. 335 · 3/5 (지난 퍼즐)` + 가림 줄 + 그리드 + 기존 `SHARE_URL`(대결 링크 없음).
- **앱**: 범위 밖(다음 티켓) — API 는 그대로 쓴다.
- **문구**: 전부 `ui_strings` 키(ko/en).

## Testing Decisions

좋은 테스트는 화면이 **무엇을 보여주는가**와 API 가 **무엇을 돌려주는가**를 본다. DOM 클래스 이름이나 내부 함수 호출 순서는 보지 않는다.

- API(대결 발급·조회, 퍼즐 번호): `tests/test_challenge_api.py`(새 파일, `tests/test_puzzle_api.py`·`tests/test_leaderboard.py` 와 같은 꼴) pytest — 실제 MySQL/Redis, 게스트 두 명을 만들어 한쪽이 끝낸 뒤 발급 → 다른 쪽이 조회. 암호문 변조·미완료·지난 퍼즐·본인 링크 케이스. 프라이어 아트: `tests/test_leaderboard*.py`, `tests/test_hint_unlock*.py`.
- 화면 계약(요소 존재·문구 사전·토큰 사용): `tests/test_web_design.py` 확장 — 모달·헤더 칩·빈 보드 5행·힌트 카드·`<dialog>`·`<details>` 사업자 정보·대결 배너 자리.
- 동작(상태 전환): `tests/test_web_js.py` + `tests/js/*.mjs` node 대역 — 첫 방문 모달 1회, 빈 행 → 피드백 행, 힌트 잠김→열림, 완료 시 시트·카운트다운, `?vs=` 배너·비교 카드·언어 불일치 버튼, 지난 대결 문구, 공유 텍스트에 링크 포함. 대역(`tests/js/harness.mjs`)에 `sessionStorage`, `dialog.showModal/close`, `location.search` 조작, `history.replaceState` 를 더한다.
- 디자인 검사: `impeccable detect` 0건(전역 규칙), 360px 스크린샷을 `design/web-shots/` 에 갱신.
- E2E: 기존 `scripts/e2e_web.sh` 시나리오 통과 + 대결 링크 왕복 시나리오 `tests/e2e/web/specs/11-challenge-link.spec.mjs` 추가(Playwright 컨텍스트 2개 = 게스트 2명; `tests/test_e2e_scripts.py` 규칙대로 ko·en 두 번 돈다, 언어 예외 없음).

- 아카이브 API: `tests/test_archive_api.py` — 지난 7일 열림·8일 전 잠김(구독자는 열림)·오늘/미래/미배정 404·제출이 Attempt 만 남기고 리더보드·GuestStats·DailyStats 를 안 건드림·끝난 퍼즐 재제출 409 `ALREADY_FINISHED`·이어서 풀기. 프라이어 아트: `tests/test_puzzle_api.py`, `tests/test_guess_flow.py`, `tests/test_entitlement.py`, `tests/test_me_history.py`(아카이브 플레이가 기록 칸에 들어가는 케이스).
- 웹: 띠 렌더(상태 점·잠금)와 `archived` 모드 보드(통계·카운트다운·대결 숨김, 공유 텍스트 `(지난 퍼즐)`)를 `tests/test_web_js.py` 시나리오로.

## Out of Scope

- iOS/Android 앱의 대결 링크·딥링크(다음 티켓. 서버 API 는 그대로 재사용).
- 무한/연습 모드(연습 전용 풀이 선행), 모음 공개 파워업, 시사 단어 카테고리(Further Notes 기획만). 아카이브의 앱 화면(다음 티켓).
- 화면 키보드(한글 조합 입력 때문에 입력창 유지).
- 광고·구독 UI(웹에는 광고 없음).
- 디자인 시스템 토큰 변경.

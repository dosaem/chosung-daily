## 2. 웹 출시 품질 업데이트 (이번에 할 것)

앱 목업 S1·S2 와 같은 수준으로 웹을 맞춘다. 디자인 시스템(OVERRIDES 토큰)은 그대로.

1. **첫 방문 "어떻게 하나요?" 모달**(온보딩 3장을 1장으로 압축) + 헤더 `?` 버튼. ko/en 문구.
2. **퍼즐 헤더**: `10월 16일 · No. N · 일반 단어` + `KST 00:00 새 퍼즐` 칩.
3. **시도 보드**: 5행 타일. 제출한 행은 `feedback` 으로 초록/회색, 남은 행은 `tile-empty`.
   (API 이미 `attempts[].feedback` 을 준다 — 서버 변경 없음)
4. **힌트 카드**: 잠김("3번째 오답 후 열려요") / 열림(힌트 문장). 웹은 광고가 없으니 보상형 버튼 없음.
5. **결과 시트**: "정답은 ○○!" · 내 그리드 · 시도별 정답자 비율 막대(API `stats`) · 다음 퍼즐 카운트다운 · 결과 공유 · 순위 보기.
6. **푸터 정리**: 약관·정책 링크 한 줄, 사업자 정보는 `<details>` "사업자 정보" 로 접기(전자상거래법 표시 의무는 유지).
7. 언어 칩은 헤더 우측 작은 토글로.
8. 완료 조건: `impeccable detect` 0건(전역 규칙), 기존 E2E 통과, 모바일 폭 360 확인.

## 3. 경쟁 서비스보다 나은 점 하나 (이번에 같이 개발) — 후보

| 후보 | 왜 차별점인가 | 비용 | 비고 |
|---|---|---|---|
| **A. 대결 링크** — 결과 공유에 `?vs=<태그>` 링크. 친구가 열면 "○○님은 2회 · 0:41 에 풀었어요" 배너, 풀고 나면 나란히 비교 | 7개 중 아무도 없음(Semantle 은 유료 Teams). 리더보드·시간 기록이 이미 있어 서버 추가가 작다. **공유 → 신규 유입** 이 혼자 만드는 앱의 가장 큰 구멍 | 중: 서버 엔드포인트 1개(태그로 오늘 결과 조회, 익명 태그만 노출), 웹 배너·비교 UI | 추천 |
| B. 모음 하나 공개 — 2번째 오답 후 "모음(중성) 하나 열기" | "Hidden Vowels" 브랜드와 정확히 맞는 고유 메커닉 | 중상: 규칙·공정성(리더보드에 표시), 앱도 바꿔야 함 | 다음 안으로 |
| C. 하루 두 문제(ko+en) 를 전면에 | 이미 있음. 경쟁사는 단일 언어 | 하: 문구·헤더만 | 2번 작업에 포함 |

**추천: A(대결 링크)** 를 이번에 구현. C 는 웹 업데이트에 문구로 녹인다.

## 4. 다음 안 3개 (기획만, 구현 안 함)

1. **지난 퍼즐 아카이브** — Contexto 식 "지난 7일" 무료, 그 이전은 구독자. 서버: 날짜 지정 조회·제출 API(오늘 퍼즐 경로 재사용, 리더보드·연속 기록에는 미반영). 웹/앱: 날짜 띠. 효과: 신규 유저가 첫날 여러 판을 해보고 습관이 붙는다.
2. **모음 하나 공개 파워업** — 2번째 오답 뒤 중성/모음 한 칸 공개(앱은 보상형 광고, 웹은 하루 1회). 공개 사용 여부를 attempt 에 기록해 리더보드 행에 작은 표시. 브랜드(Hidden Vowels)와 직결되는 고유 메커닉.
3. **시사 단어 카테고리(LLM 파이프라인 확장)** — 한국일보 초성퀴즈처럼 "이번 주 뉴스에서 나온 단어" 주 1회(수요일). 생성 프롬프트에 최근 뉴스 헤드라인(RSS)을 넣고 같은 심사·승인 흐름을 탄다. 일요일 책 제목처럼 요일 카테고리 하나 추가.

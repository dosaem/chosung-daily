# 광고 제거 구독의 권한은 서버가 스토어 영수증을 검증해서 판단한다

> 정본. 계획 당시 원본은 `.scratch/store-launch/adr/` 에 그대로 있고, 갱신은 이 사본에 한다.

구독 상태를 앱 로컬(플러그인 캐시)에만 두면 기록이 서버 게스트에 묶여 있는 이 서비스에서 다른 기기·전환 후에 광고가 다시 켜진다. 그래서 앱은 구매/복원 때 영수증(iOS JWS, Android purchase token)만 서버에 넘기고, 서버가 App Store Server API / Google Play Developer API 로 검증해 만료일을 저장한다. 구독 권한 = 만료일이 미래. 갱신·해지 추적은 스토어 웹훅(App Store Server Notifications, Play RTDN) 대신 Beat 가 매일 만료 임박 구독을 재조회하는 폴링으로 한다 — 웹훅은 Pub/Sub 등 사람 설정이 많고 이 규모엔 하루 지연이 허용된다. RevenueCat 같은 외부 서비스는 면접에서 설명할 코드가 줄어서 쓰지 않는다.

**Considered**: RevenueCat(빠르지만 블랙박스), 앱 로컬 판단(기기 간 불일치), 스토어 웹훅(설정 비용, 나중에 추가 가능).

**상태 판정**: 스토어 상태를 `active|grace|hold|expired|revoked|replaced` 로 정규화한 뒤 순수 함수로 권한을 판정한다 — active 는 만료+24h 까지, grace 는 스토어 유예 종료까지, 나머지는 없음. 24h 유예는 "갱신됐는데 서버가 모름" 만 흡수하고 확인된 철회·보류에는 적용하지 않는다. 앱은 시작·복귀 때 스토어 구매를 동기화해 영수증을 다시 보내므로 ±24h 밖의 복구도 즉시 반영된다.

**재조회(스펙 §A.8 기준)**: `/me/stats` 호출 시 `status ∈ {active, grace, hold}` 인 구독은 `last_verified_at` 이 **1시간**보다 오래됐으면 만료 구간과 무관하게 스토어를 재조회한다(만료 ±24h 안이면 1시간 상한 없이 매 호출 재조회). 타임아웃 3초, 실패 시 저장값 유지. 응답의 `entitlement.next_check_at` = `last_verified_at + 1h` 이고, 앱은 포그라운드에서 그 시각에 맞춰 `/me/stats` 를 다시 불러 권한 변화를 광고 상태에 반영한다. 그래서 철회 감지 지연은 포그라운드 세션에서 최대 1시간 + 타이머 오차다.

**Consequences**: 해지 후 만료일까지는 광고 없음(정상). Beat 폴링만 보면 해지 반영이 최대 하루 늦을 수 있지만, 위 1시간 TTL 재조회가 `/me/stats` 경로에서 그 지연을 메운다. **갱신 반영 지연은 24시간 유예 + 만료 ±24h 구간의 무상한 동기 재조회로 흡수**한다 — 돈 낸 구독자가 광고를 보는 일이 없어야 하므로. App Review 는 프로덕션 서버에 Sandbox 영수증을 보내므로 JWS `environment` 로 엔드포인트를 고르고 4040010 이면 Sandbox 로 재시도한다. 웹훅 도입은 폴링을 대체하는 게 아니라 보완하는 형태로 미정 항목에 둔다.

# Play 데이터 보안(Data safety) 답안 초안 (티켓 35)

Play Console → 앱 콘텐츠 → **데이터 보안** 설문의 답안이다. 콘솔 입력은 사람이 하고
(`docs/RELEASE.md` "### 35."), 이 문서가 **그 입력의 정본**이다. 같은 사실을 세 곳
(개인정보처리방침 · ASC 개인정보 라벨 · Play 데이터 보안)에 적어야 해서, 세 곳이
어긋나지 않게 대조표를 `docs/legal-checklist.md` "스토어 라벨" 절에 두고
`tests/test_store_labels.py` 가 그 표를 지킨다.

기준 문서: `web/templates/legal/privacy.{ko,en}.html` 의 `#collection`(수집 항목)과
`#overseas`(국외 이전). **방침에 없는 수집을 여기 적지 않고, 방침에 있는 수집을
여기서 빼지 않는다.**

## 1. 보안 관행 (설문 첫 화면)

| 질문 | 답 | 근거 |
|---|---|---|
| 전송 중 데이터 암호화 | 예 | 앱은 HTTPS(`https://chosung.dosaem.com/api/v1`)로만 통신한다. 광고·분석·오류 SDK 도 각사 HTTPS 엔드포인트로 직접 보낸다 |
| 사용자가 데이터 삭제를 요청할 수 있음 | 예 | 앱 "내 기록 > 계정 삭제", 웹 `https://chosung.dosaem.com/account/delete`(방침 `#rights`) |
| 데이터 수집·공유 관행이 Play 패밀리 정책을 따름 | 해당 없음 | 만 14세 미만 대상 앱이 아니다(방침 `#children`) |
| 독립적인 보안 검토를 받았음 | 아니요 | 받지 않았다. 받지 않은 검토를 받았다고 적지 않는다 |

## 2. 데이터 유형 (설문 본문)

"공유" 는 Play 기준의 제3자 전송이다 — 방침 `#overseas` 의 받는 자가 있으면 공유다.
"필수" 는 그 데이터 없이는 기능이 돌지 않는다는 뜻이고, 사용자가 켜고 끌 수 있으면
선택이다.

| `/privacy` `#collection` 항목 | Play 데이터 유형 | 수집 | 공유 | 필수/선택 | 목적 | 비고 |
|---|---|---|---|---|---|---|
| 게스트 토큰 | 개인 정보 > 사용자 ID | 예 | 아니요 | 필수 | 앱 기능 | 기록의 주인. 첫 실행에 서버가 발급한다. 앱은 이 값을 기기 보안 저장소(iOS 키체인 · Android 암호화 저장소)에 두고, iOS 는 앱을 지워도 남는다 — 방침 `#automatic-collection` 의 "기기 보안 저장소" 항목이 저장 위치·지우는 방법을 적는다(티켓 47) |
| 계정 이메일 | 개인 정보 > 이메일 주소 | 예 | 아니요 | 선택 | 앱 기능, 계정 관리 | 구글·애플 계정을 연결할 때만 |
| 애플 refresh token | 개인 정보 > 기타 정보 | 예 | 예 (Apple) | 선택 | 계정 관리 | 계정 삭제 시 애플 연결 철회에 쓴다 — 그때 Apple 로 전송된다(방침 `#overseas` 애플 행) |
| 시도 기록 | 앱 활동 > 기타 사용자 제작 콘텐츠 | 예 | 아니요 | 필수 | 앱 기능 | 제출 단어·정답 여부·시도 횟수·연속 기록 |
| 오늘의 순위 | 앱 활동 > 기타 사용자 제작 콘텐츠 | 예 | 아니요 | 필수 | 앱 기능 | 같은 유형이라 한 칸으로 답한다. 표시 이름은 익명 번호 |
| 구독 식별자 | 금융 정보 > 구매 내역 | 예 | 예 (Google, Apple) | 선택 | 앱 기능 | 구매 토큰·거래 ID·만료 시각. 결제 수단은 서버로 오지 않는다 |
| 광고 ID | 기기 또는 기타 ID | 예 | 예 (Google AdMob) | 필수 | 광고 또는 마케팅 | SDK 가 직접 보내고 서버에 저장하지 않는다 |
| 광고 ID(노출·클릭 측정) | 앱 활동 > 앱 내 상호작용 | 예 | 예 (Google AdMob) | 필수 | 광고 또는 마케팅, 분석 | 광고 노출·클릭. 구독자는 광고 자체가 없다 |
| 광고 요청 정보(대략적 위치) | 위치 > 대략적인 위치 | 예 | 예 (Google AdMob) | 필수 | 광고 또는 마케팅 | 위치 권한은 쓰지 않는다 — AdMob SDK 가 광고 요청의 IP 로 추정한다(방침 `#overseas` AdMob 행). 기기 밖으로 나가는 값이라 신고한다 |
| 앱 사용 이벤트 | 앱 활동 > 앱 내 상호작용 | 예 | 예 (Google Firebase) | 필수 | 분석, 앱 기능 | 퍼즐 완료·공유·구독 화면 조회·구독 시작 4개(방침 `#overseas` Firebase 행) |
| 접속·오류 기록(Sentry) | 앱 정보 및 성능 > 비정상 종료 로그 | 예 | 예 (Sentry) | 필수 | 앱 기능 | 오류 스택. 요청 본문·쿠키·IP·식별자는 보내지 않는다 |
| 접속·오류 기록(Sentry) | 앱 정보 및 성능 > 진단 | 예 | 예 (Sentry) | 필수 | 앱 기능 | 느린 요청·지연 정보 |
| 접속·오류 기록(접속기록) | 앱 정보 및 성능 > 기타 앱 성능 데이터 | 예 | 아니요 | 필수 | 앱 기능, 보안 | 개인정보 처리 행위의 접속기록(행위자·원격 IP·행위·결과)과 접근 로그 파일. 법정 보관 1년(고시 §8①) |

### 이 표에 **없는** 것

| Play 데이터 유형 | 왜 아닌가 |
|---|---|
| 이름 / 주소 / 전화번호 | 받지 않는다. 로그인은 OAuth 고 받는 건 이메일·식별자뿐이다 |
| 결제 정보 | 스토어가 처리하고 서버로 오지 않는다(방침 `#collection` 구독 식별자) |
| 정확한 위치 | 위치 권한(`ACCESS_FINE_LOCATION`)이 없고 GPS 를 읽지 않는다. **대략적인 위치는 위 표에 있다** — AdMob 이 IP 로 추정하는 값은 우리 서버에 저장하지 않아도 SDK 가 기기 밖으로 보내므로 수집·공유 신고 대상이다([AdMob 데이터 공개](https://developers.google.com/admob/android/privacy/play-data-disclosure), [Play Data safety 설명](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)) |
| 연락처 / 사진 / 동영상 / 오디오 / 파일 | 권한 자체가 없다(`AndroidManifest.xml`) |
| 검색 기록 | 앱에 검색이 없다. 운영자 화면의 단어 검색은 플레이어 앱 밖이다 |
| 설치된 앱 / 기기 ID(광고 ID 외) | 수집하지 않는다 |
| 건강·피트니스 / 메시지 / 캘린더 | 해당 기능이 없다 |

## 3. 사람이 확인할 것

- 콘솔 입력 후 "미리보기" 의 요약이 이 표와 같은지 한 번 비교한다(`docs/RELEASE.md` "### 35.").
- 광고 SDK·구독이 들어오는 티켓(31·32)이 전송 항목을 늘리면 **이 문서와 ASC 라벨과
  방침 세 곳을 같이** 고친다. 한 곳만 고치면 `tests/test_store_labels.py` 가 깨진다.
